Performing non-disruptive upgrade operations

This task describes how to perform non-disruptive upgrade operations.

Step 1: Upgrading the PFMP

You can upgrade the PFMP by calling this API:

POST /Api/V1/Appliance/upgrade

Here is a sample payload for three nodes:

{
  "location": "http://192.168.201.2/artifactory/vxfm-yum-release/pfmp20/PFMP2-4.6.0.0-1036.tgz",
  "username": "",
  "password": "",
  "nodes": {
    "nodes": [
      {
        "name": "pfmp452-46-bvt-mvm-1", <=== hostname of k8s node 1
        "ipAddress": "192.168.201.31",        <=== ip of k8s node 1
        "username": "root",
        "credential": {
          "name": "pfmp452-46-bvt-mvm-1",
          "type": "password",
          "password": "admin"
        }
      },
      {
        "name": "pfmp452-46-bvt-mvm-2",
        "ipAddress": "192.168.201.32",
        "username": "root",
        "credential": {
          "name": "pfmp452-46-bvt-mvm-2",
          "type": "password",
          "password": "admin"
        }
      },
      {
        "name": "pfmp452-46-bvt-mvm-3",
        "ipAddress": "192.168.201.33",
        "username": "root",
        "credential": {
          "name": "pfmp452-46-bvt-mvm-3",
          "type": "password",
          "password": "admin"
        }
      }
    ]
  }
}

After upgrading the PFMP, check the status by calling this API:

GET /Api/V1/corelcm/status

Here’s a sample response body:


{
  "lcmStatus" : "UPGRADING",
  "clusterVersion" : "4.5.2.0",
  "clusterBuild" : "120"
}

Allow unsigned RCM

If the state returned from the GET is “needapproval”, you can allow an unsigned RCM by calling this API:

PUT /Api/V1/FirmwareRepository/8aaa8d3e8db2b115018db31bb5c806f2/allowunsignedfile

Set the RCM to be the default catalog

If the state is “available” and defaultCatalog in the create payload is “true”, set this RCM to defaultCatalog by calling this API:

PUT /Api/V1/FirmwareRepository/8aaa8d3e8db2b115018db31bb5c806f2

You can update the PowerFlex gateway by following the steps below.

Get the identifier

Get the identifier by calling this API:

POST Api/V1/Deployment/getcomponentbyips

Here is a sample payload:


{"ipAddresses":["192.168.201.37"]}
Sample output:

Update the gateway

Update the gateway by calling this API:

PUT /Api/V1/ManagedDevice/firmware

Here is a sample payload:


{
  "idList": [
    "scaleio-block-legacy-gateway"
  ],
  "device Update List": [  
    " b7b0087f00000000",             
    " b7b0087f00000001",
    " b7b0087f00000002"
  ],
  "scheduleType": "updatenow",
  "exitMaintenanceMode": false,
  "scheduleDate": "",
  "updateType": "GATEWAY",
  "option": "protected",
  "reconfigure": false
}

Use the “device Update List” to pass in the list of IDs you previously retrieved from the deployment:


["deployment"]["serviceTemplate"]["components"][0]["identifier"]

For a software-only deployment, check the “deviceType” and “ipAddress” properties. The “deviceType” should be “SoftwareOnlyServer” and the “ipAddress” should be the software-only VM IP address.
For a rack deployment, check the “deviceType” and “osIpAddress” properties. The “deviceType” should be “RackServer” and the “osIpAddress” should not be empty.

Update a resource group

You can update a software-only resource group by calling this API:

PUT /Api/V1/ManagedDevice/updateAsync

Here is a sample payload:


["softwareOnlyServer-192.168.201.36",  <== refId from previous step
"softwareOnlyServer-192.168.201.37",
"softwareOnlyServer-192.168.201.35"]

See the list of refId values returned by managed_device get_by_id /Api/V1/ManagedDevice/softwareOnlyServer-192.168.201.36

You can update a rack resource group by calling this API:

PUT /Api/V1/ManagedDevice/firmware

Here is a sample payload:


{
  "idList": [
    "8aaa2dcf8de82bcd018de86f33b704ed",
  ],
  "deviceIdToUpdateList": [ <== refId from managed_device get
    "ad22b50400000001",
    "ad22b50500000002",
    "ad22b50300000000"
  ],
  "scheduleType": "disruptiveupdate",
  "exitMaintenanceMode": false,
  "scheduleDate": "",
  "updateType": "SERVICE",
  "option": "protected",
  "reconfigure": false
}

The idList shows a list of serviceReference id values from managed_device Get_by_id. The deviceIdToUpdateList shows a list of refId values from managed_device Get_by_id.
