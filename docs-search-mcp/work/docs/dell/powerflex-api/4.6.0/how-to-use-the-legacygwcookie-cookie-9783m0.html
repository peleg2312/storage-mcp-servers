How to use the LEGACYGWCOOKIE cookie?

PowerFlex management platform (PFMP) contains two block-legacy-gw pods. Each pod is its own independent instance of the gateway. Whenever you send an API to the gateway, it will reach one of the pods randomly.

This is fine for APIs under the /api prefix because they are stateless, but causes an issue for the APIs under the /im prefix.

This is because the /im realm contains orchestrations which hold state. Two orchestrations running in parallel (each on a separate node) and tracking the state of a running orchestration might cause issues because each pod is oblivious to the state of an orchestration running on the other pod.

For example,

When running CSV install using the /im/types/Configuration/actions/install, the request reaches gateway pod #1.

If you want to see the progress of the install using /im/types/ProcessPhase/actions/queryPhaseState, the request reaches gateway pod #2 and returns idle state, even though the install is still running on pod #1. To prevent such scenarios, we need to use the LEGACYGWCOOKIE. Also, use this cookie when using /im/types/Command/instances/actions/clear, /im/types/Command/instances/actions/abort, and /im/types/ProcessPhase/actions/moveToIdlePhase APIs.

To get the cookie, run GET request, for example, /im/types/Command/instances.

The response will contain the cookie, for example:

set-cookie: LEGACYGWCOOKIE=1680712209.587.12470.670589|44462cccff00556f36e19b74466d15cc; Path=/im/(.*); Secure; HttpOnly

Use this cookie in all subsequent /im requests. Here is an example how to include it in a curl request:

curl -X \
 GET -s -k --location \
\
--header \
 "Authorization: Bearer ${ACCESS_TOKEN}" 
--header \
 "Content-Type: application/json" -b "LEGACYGWCOOKIE=832ac040587651c1dc5b8e0581f2d3eb|44462cccff00556f36e19b74466d15cc; 
 Path=/im/(.*); Secure; HttpOnly" "https://${INGRESS_IP}/im/types/Command/instances"
