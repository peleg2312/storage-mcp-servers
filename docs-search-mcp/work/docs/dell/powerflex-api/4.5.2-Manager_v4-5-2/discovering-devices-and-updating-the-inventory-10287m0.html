Discovering devices and updating the inventory

Device Discovery

Discovering devices is initiated by creating a DiscoveryRequest with a discoveryRequestList. The
discoveryRequestList contains a list of DiscoverIPRangeDeviceRequest’s each of which specifies:

  • The IP address range to discover defined by deviceStartIp and (optionally) deviceEndIp. If
    deviceEndIp is not specified only deviceStartIp will be discovered.
  • The deviceType which should be set to one of the following values depending on type of device
    being discovered: genericswitch, Server, vcenter, scaleio or em. em should be used for
    discovering Panduit IPI cabinets.
  • The Credential to use for discovery. This must be specified as one of the following parameters
    depending on the deviceType being discovered: deviceServerCredRef, deviceSwitchCredRef,
    deviceVCenterCredRef, deviceScaleIOCredRef or deviceEMCredRef. The value should be the
    Credential id.

A sample request issued to POST /Api/V1/DiscoveryRequest is:

{
   "discoveryRequestList": {
       "DiscoverIPRangeDeviceRequest": [
           {
               "deviceEndIp": "100.68.112.33",
               "deviceServerCredRef": "fd9e94f6-703e-42b3-8287-ec1b9e785926",
               "deviceStartIp": "100.68.112.30",
               "deviceType": "Server",
               "reserved": false,
               "serverPoolId": "",
               "unmanaged": false
           }
       ]
   }
}

Sample response is:

{
    "devices": null,
    "discoveryRequestList": {
        "DiscoverIPRangeDeviceRequest": [ ... omitted ... ]
        "discoverIpRangeDeviceRequests": [ ... omitted ... ]
    },
    "id": "Job-7d163350-c1a0-4052-aa0e-420c6754083b",
    "link": null,
    "status": "INPROGRESS",
    "statusMessage": null,
    "totalCount": 0
}

The discovery request has now been initiated and a job created for it identified by
Job-7d163350-c1a0-4052-aa0e-420c6754083b. Monitoring the status of this job is done by calling
GET /Api/V1/DiscoveryRequest/{job_id}

Sample response to GET /Api/V1/DiscoveryRequest/Job-7d163350-c1a0-4052-aa0e-420c6754083b:

{
    "devices": [],
    "discoveryRequestList": {
        "DiscoverIPRangeDeviceRequest": [ ... omitted ... ]
        "discoverIpRangeDeviceRequests": [ ... omitted ... ]
    },
    "id": "Job-9282b26f-1eb3-4b18-a12d-daf5254c49a5",
    "link": null,
    "status": "INPROGRESS",
    "statusMessage": "Inprogress",
    "totalCount": 0
}

The DiscoveryRequest will be removed and return 404 once the job is complete. In order to verify
that the expected device was successfully discovered and added as a Resource it can be retrieved
either by the IP address it was discovered with or with the service tag:

  • Search by ip address: GET /Api/V1/ManagedDevice?filter=eq,ipAddress,100.68.112.30
  • Search by service tag: GET /Api/V1/ManagedDevice?serviceTag=eq,serviceTag,XXXXXX

Device Inventory

If configuration is changed on devices outside of PowerFlex Manager (for example, adding or changing
settings in vCenter or PowerFlex) it is important to re-inventory those devices so that PowerFlex
Manager has a view of those changes. This inventory will happen automatically on a nightly cadence
for most device types, or hourly for the PowerFlex Gateway. Inventory can also be triggered earlier
via the REST API as described here.

To initiate a new inventory job on an existing device execute
POST /Api/V1/ManagedDevice/update?deviceId={refId}. The refId can be found by running
GET /Api/V1/ManagedDevice.

Sample response:

[
    {
        "jobName": "Job-6ff9d2ac-f47f-452f-a5f4-8b16fcca2974"
    }
]

The job can be polled to monitor for successful completion via
GET /Api/V1/JobHistory/{job_id}/status, e.g.
GET /Api/V1/JobHistory/Job-6ff9d2ac-f47f-452f-a5f4-8b16fcca2974/status

Sample response:

"IN_PROGRESS"

The response is a string value indicating the current status of the job. Possible return values are:
"STARTING", "IN_PROGRESS", "SUCCESSFUL", "FAILED", "CANCELLED" and
"ABNORMAL_TERMINATION". Once the job is no longer "STARTING" or "IN_PROGRESS" it is complete.
