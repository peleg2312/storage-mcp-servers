Common APIs for Erasure Coding and Mirroring > PowerFlex Security Engine REST API > security-settings

Instance update

Updates the ingresses list by completing one of the following options:

  • Replacing the entire list (ingresses)
  • Adding new entries (add_ingresses)
  • Removing entries (remove_ingresses)

Only one option is allower per API call.

Load balancer (LB) ingress entries cannot be removed.

Where the ingresses option is provided, it replaces the existing list, except for any load balancer IPs, which are preserved.

In rare cases, a 299 HTTP status code is returned. The status code means the operation succeeded with a warning.

This warning occurs if the payload includes an “ingresses” field and any item in that list meets one of the following conditions:

  • The network name already exists in the system but is associated with a different IP address.
  • The IP address for that network name is missing (empty) in the payload.

Bad Request. In STRINGENT or STANDARD_TO_STRINGENT modes, the hostname field must not be empty. You cannot use ingresses in combination with add_ingresses or remove_ingresses. These options are mutually exclusive. To remove ingress in the payload: - Entries in the remove_ingresses list must include a valid network name—empty values are not permitted. - remove_ingresses must not contain entries that are currently active in the system’s ingress list (e.g., kubeops load balancer IPs).
