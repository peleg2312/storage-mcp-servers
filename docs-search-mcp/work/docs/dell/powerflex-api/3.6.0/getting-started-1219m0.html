Getting started

Prerequisites for connecting to the API

If you installed the PowerFlex Gateway manually, ensure that the MDM connection properties are configured correctly in the PowerFlex Gateway configuration file.

If the PowerFlex Installer was used to install PowerFlex, the MDM connection properties are already configured in
the PowerFlex Gateway configurtation file, and no action is required.

Run a self-test to verify connectivity and correct configuration:

  1. From a browser: Navigate to the login page at this URL: https://<GATEWAY_IP_ADDRESS>/api/login.
  2. Log in as an admin user, using the MDM password.

If a message is returned that a connection cannot be established, the PowerFlex Gateway requires configuration. To configure the Gateway, see Configure the PowerFlex Gateway using the REST API.

NOTE:

A PowerFlex Gateway deployed on RHEL 6.x requires a specific version of NSS. For more information, see “Approved encryption methods” in the PowerFlex User Guide.

NOTE:

You can query the Gateway configuration at any time to verify whether the MDM IP addresses are configured:
https://<server_ip>:443/api/Configuration

For reponse details, see Query the PowerFlex Gateway configuration.

User permissions

REST command execution is allowed according to the user role and permissions. These roles are explained in detail in the PowerFlex User Roles and LDAP Usage Technical Notes.

Authentication

The PowerFlex API uses HTTP Basic authentication. To connect to the PowerFlex Gateway to configure PowerFlex, invoke an HTTP GET request that includes the PowerFlex Gateway’s IP address, followed by /api/login:
https://<GATEWAY_IP_ADDRESS>/api/login

Example:

https://10.76.60.190:443/api/login
GET

NOTE:

When running a GET command, the json is empty.

Log in as an admin user, using the MDM password. A token is returned.

For a list of commands requiring the gatewayAdminPassword, see gateAdminPassword.

User token

The login request returns a token in response. This token is valid for eight hours from the time it was created, unless there has been no activity for 10 minutes or the client has sent a logout request. When working directly in REST client, the user will be asked to refresh the token.

For every subsequent REST API request that does not require the gatewayAdminPassword, pass the token as the password in the HTTP Basic authentication. The user is ignored and can be empty.

Secured communications

You can set the PowerFlex Gateway to work with secured communications with the MDM (POST):

https://<server>:<port>/api/gatewaySetSecureCommunication

Log in as an admin user, using the gatewayAdminPassword.

The PowerFlex Gateway will be unable to connect to the MDM using non-secured communications.

HTTP token invalidation (logout)

To invalidate the token, invoke the HTTP GET request with the URI, followed by /api/logout. The user is ignored and can be empty.

Example:

https://10.76.60.190:443/api/logout
GET

REST API version

The REST API version should be added to the Accept parameter in the header field. For example:
Accept: application/ json;version=1.0

If no Accept header field is present, it is assumed that the client accepts all media types and versions.

URIs

General URIs

POST (create) / GET all objects for a given type
/api/types/{type}/instances

GET by ID
/api/instances/{type::id}

POST a special action on an object
/api/instances/{type::id}/action/{actionName}

POST a special action on a given type
/api/types/{type}/instances/action/{actionName}

Get current API version
/api/version

GET all instances
/api/instances/

Logs

Logs for REST activity are saved in the following locations on the PowerFlex Gateway:

  • Windows: C:\Program Files\EMC\ScaleIO\Gateway\logs\api_operations.log
  • Linux: /opt/emc/scaleio/gateway/logs/api_operations.log
