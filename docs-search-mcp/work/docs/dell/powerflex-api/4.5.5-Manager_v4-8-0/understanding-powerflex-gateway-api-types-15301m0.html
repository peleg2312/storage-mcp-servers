Understanding PowerFlex gateway API types

PowerFlex gateway provides two distinct REST API services, each with a unique prefix:

  • PowerFlex REST API: Uses /api/ prefix
  • PowerFlex Installation Manager (IM) REST API: Uses /im/ prefix

Distinction between PowerFlex REST API and Installation Manager (IM) REST API

Aspect PowerFlex REST API (/api/) IM REST API (/im/)
Purpose Exposes MDM functionality using REST (similar to SCLI) Manages operations including install, upgrade, and OS patching)
Scope Single object or action per request Primarily asynchronous (HTTP 202); but some endpoints are synchronous (for example, POST /im/types/Configuration/instances returns the Configuration JSON directly)
Execution model Synchronous - returns result immediately Asynchronous—returns HTTP 202 for long-running operations
Backend communication Protocol Buffers (protobuf) over TCP to MDM SSH or LIA to target cluster nodes and MDM
Data model In-memory cached MDM model (auto-polled) Declarative Configuration JSON (client-provided)
Statefulness Stateless—requests can route to any pod Stateful—operation state persists on the initiating pod

Authentication for PowerFlex gateway APIs

Both /api/ and /im/ endpoints use unified PowerFlex Management Platform (PFMP) cluster authentication using Keycloak. There is no authentication difference between the two API types.

Authentication methods:

Method 1: Keycloak token authentication

Login endpoint:

POST /rest/auth/login
Content-Type: application/json

{
  "username": "admin",
  "password": "<password>"
}

Response: Returns a Keycloak access token

Subsequent requests: Use the same Bearer token for both /api/ and /im/ endpoints:

Authorization: Bearer <access_token>

Method 2: Legacy login endpoint (Backward compatible)

Login Endpoint:

GET /api/login
Authorization: Basic <base64-encoded-credentials>

/api/login authenticates against Keycloak (PFMP) and returns a token that works for both /api/ and /im/.
